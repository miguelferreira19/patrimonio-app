# Reforma da app · plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tornar a app de rendas clara no telemóvel (quem deve, quanto, desde quando), com papel de
gestor, recolha de várias contas pronta para a herança, cartas, calendário fiscal e um controlo de
emissão só para o administrador.

**Architecture:** A lógica nova vive em módulos puros de `src/lib` com `*.check.ts`; as páginas
(server components) só compõem. O schema cresce por um bloco aditivo (`supabase/reforma.sql`),
compatível com o código que está em produção. A recolha Python ganha contas, anulados e um registo
de observações que alimenta o Controlo.

**Tech Stack:** Next.js (App Router), Tailwind v4, Supabase (Postgres, RLS, RPC), Python
(Playwright, psycopg, pandas). Sem dependências novas.

**Spec:** `docs/superpowers/specs/2026-11-11-reforma-design.md`

## Global Constraints

- PT-PT em todo o texto da interface. Proibido na UI: travessões, emojis, gradientes, animações
  infinitas. Não há verde de "ok".
- Node não está no PATH: `export PATH="/c/Users/migue/AppData/Local/Logi/LogiPluginService/PluginHosts/node22/node:$PATH"`.
- Porta de cada tarefa: `npm run check` verde e `npx tsc --noEmit` sem erros. **Nenhum agente
  corre `npm run build`** (partilha a `.next` com o dev); o build é da porta de fase.
- Schema só aditivo, idempotente, em `supabase/reforma.sql` e repetido no fim de
  `supabase/schema.sql`. Nenhum agente aplica SQL na base.
- Leituras por `linhas()`/`linha()` (`lib/supabase/dados.ts`) e `paginateAll`; nunca
  `(q.data ?? []) as T[]`. Escritas só em server actions (`lib/actions/*`) com `requireAdmin` ou
  `requireGestor`, validadas por `lib/validar.ts`.
- `src/components/ui.tsx` e `kit/` nunca levam `"use client"`.
- Todo o euro passa por `<Money>`; nomes por `nomeProprio()`, frações por `nomeDaFracao()`, meses
  por `monthLabel()`.
- Ficheiros até 400 linhas, funções até 50. Código novo usa só tokens semânticos.
- Nenhum agente lê `dados/` além dos `.py`. Nada de `dados/` vai para o git.
- Ramo `reforma`. Commits por tarefa (`feat:`, `fix:`, `docs:`), sem push até à porta de fase.
- Cores e tipografia: as do §9 da spec, copiadas à letra.

## Review Focus

1. **Recibo anulado depois de importado como emitido:** o mês tem de voltar a "em atraso" ou "por
   receber" e sair dos totais (teste na Tarefa 0.4).
2. **Uma conta do Portal falha a meio da recolha:** as outras contas concluem, o erro fica em
   `collection_runs` e o processo sai com código diferente de zero (teste na Tarefa 0.3).
3. **Gestor tenta uma ação de admin por chamada direta à action:** recusa no servidor com mensagem
   clara, mesmo que o botão não exista (teste na Tarefa 0.2).
4. **Carteira sem nenhum atraso:** Início e Rendas mostram o estado calmo, sem blocos vazios nem
   "0 €" a laranja (teste na Tarefa 2.1).
5. **Recibo sem `first_seen` (anterior a 17/08/2026):** o Controlo não lhe inventa um atraso de
   emissão; fica fora das medianas e é contado como "sem medição" (teste na Tarefa 6.1).
